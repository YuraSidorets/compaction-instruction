Before you write your reply for this stage, save the tracked state of the task to the clock. First, call the ctx_clock_status tool with no arguments. Its reply gives the current revision (state_rev) and the ids of recent events. Then call the ctx_clock_commit tool once, with three fields. The field expectedRevision is the state_rev number from the status reply. The field summary is one short line about the task state. The field findings is a list, and each finding has a text and an evidence list. Together, the finding texts must hold every tracked value that is current now, each written with its exact identifier and its exact value, in the form "<identifier>: <value>". For each tracked item whose value changed during the task, also write its earlier values in order, the first value first, in the form "<identifier> history: <first value>, then <next value>". One finding can hold several values. Use at most 12 findings. The evidence list of each finding must hold at least one event id from the status reply. If the commit is rejected, read the error line, call ctx_clock_status again, and commit again with the corrected fields.
